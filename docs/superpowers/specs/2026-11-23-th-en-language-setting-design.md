# ImproveFlow: ตั้งค่าภาษาไทย / English ทั้งแอป

## เป้าหมาย

ให้ผู้ใช้เลือกภาษาไทยหรือ English ได้ทุกหน้าจอที่เปิดใช้จริง ไม่ใช่แค่ขั้นตอน Request → Solution → Final โหมดไทยใช้คำสั้น ๆ ที่คุ้นเคย และคงคำอย่าง Request, Solution และ Final ไว้เมื่ออ่านง่ายกว่าคำแปล

**ชื่อ Status ไม่แปลและไม่แก้** ทั้งชื่อที่เห็นบนหน้าจอและค่าที่ระบบใช้ กฎอนุมัติ สิทธิ์ และข้อมูลที่เก็บไว้ไม่เปลี่ยนตามภาษา

## วิธีที่เลือก

- **จำตามบัญชี (เลือกวิธีนี้):** ภาษาตามไปเมื่อใช้บัญชีเดียวกันบนคอมหรือมือถือ ต้องเพิ่มช่องเก็บค่าในฐานข้อมูล แต่ผู้ใช้ไม่ต้องเลือกใหม่ทุกเครื่อง
- **จำตามเบราว์เซอร์อย่างเดียว:** ไม่ต้องเปลี่ยนฐานข้อมูล แต่ไม่ตามบัญชีข้ามเครื่อง และอาจใช้ค่าคนก่อนหากแชร์เบราว์เซอร์ จึงใช้ค่าเบราว์เซอร์แยกเฉพาะก่อนล็อกอิน
- **แปลเฉพาะขั้นตอน Request → Final:** ส่งงานได้เร็วกว่า แต่จะเหลือหน้าที่คนต้องสลับกลับไปอ่าน English จึงขยายเป็นทุกหน้าจอในงานเดียว แบ่งทำและทดสอบเป็นชุดได้ แต่ไม่ถือว่าเสร็จจนกว่าจะครบ

## การเลือกภาษา

```text
ก่อนล็อกอิน: หน้า Sign In / Sign Up → ภาษา / Language → ไทย · English
หลังล็อกอิน: รูปโปรไฟล์ → ภาษา / Language → ไทย · English
```

- ใช้ชื่อ `ไทย` และ `English` เหมือนกันทั้งสองโหมด ให้เห็นและอ่านได้ว่าภาษาไหนกำลังใช้อยู่ ใช้คีย์บอร์ดเลือกได้และแตะได้บนมือถือ
- ก่อนล็อกอินใช้ English จนกว่าจะเลือก แล้วจำค่านั้นในเบราว์เซอร์สำหรับหน้าที่ไม่ต้องล็อกอิน ไม่เดาภาษาจากเครื่องและไม่ใช้ค่านี้เขียนทับบัญชี
- หลังล็อกอินใช้ค่าของบัญชีเท่านั้น บัญชีเดิมและบัญชีใหม่เริ่มที่ English จนกว่าจะเลือกเอง บัญชีอื่นไม่รับค่าภาษาของบัญชีก่อนหน้า
- เมื่อบันทึกสำเร็จ หน้าเดิมเปลี่ยนภาษาโดยไม่ต้องล็อกอินใหม่ ไม่เปลี่ยน URL ไม่ล้างตัวกรองหรือข้อมูลที่กำลังกรอก หากบันทึกไม่สำเร็จ ให้คงภาษาเดิมและบอกให้ลองใหม่ได้

## ขอบเขต: ทั้งแอป ไม่รวมอีเมลและ Export

| กลุ่มหน้าจอ | ข้อความที่รองรับสองภาษา |
| --- | --- |
| ก่อนล็อกอินและบัญชี | Sign In, Sign Up, Change Password, Profile, Approval Chain, เมนูและการนำทางบนมือถือ/เดสก์ท็อป |
| Request และ Engineering | My Requests, Pending Approvals, รายการงาน Engineering, ตารางและการ์ด ตัวกรอง รวมทุกหน้าต่างของ Request → Solution → Final เช่น ส่ง อนุมัติ ไม่อนุมัติ และส่งใหม่ |
| Dashboard และรายงานในแอป | Dashboard, Workflow, Analytics, Budget Monitor รวมชื่อแกน ป้ายอธิบายกราฟและคำอธิบายที่แอปกำหนด ยกเว้นชื่อที่เป็น Status จริง |
| Admin | หน้าหลัก, Users, Organization, Approval Routes, Templates, Sub-task Stages, Storage, Retention, Email Settings, Deleted Requests และ Audit รวมหน้าสร้าง/แก้ไขและข้อความยืนยัน ปุ่ม Export แปลได้ แต่ไฟล์ที่ได้ไม่เปลี่ยน |
| แจ้งเตือนในแอป | หัวข้อ ปุ่ม เมนู และข้อความแจ้งเตือนใหม่ที่ระบบสร้าง รวมคำบอกเวลาแบบ “เมื่อ 2 ชั่วโมงก่อน” |
| ข้อความร่วม | ปุ่ม ชื่อช่อง คำแนะนำ ข้อความกำลังโหลด/ไม่มีข้อมูล/ไม่พบหน้า ข้อความยืนยันและแจ้งข้อผิดพลาดที่แอปควบคุม รวมถึงป้ายสำหรับโปรแกรมอ่านหน้าจอ |

### สิ่งที่คงเดิม

- ชื่อ Status ใน badge ตาราง การ์ด timeline หน้ารายละเอียด ตัวเลือกตัวกรองและกราฟ รวม `Final Approval`, `Pending`, `Approved`, `Rejected`, `Completed` เป็นต้น แปลหัวข้อ `Status` เป็น `สถานะ` ได้ แต่ไม่แปลค่าข้างใต้ ไม่ปรับการสะกดเดิมให้เหมือนกันข้ามหน้า
- ชื่อเรื่อง รายละเอียด คอมเมนต์ เหตุผลที่คนกรอก ชื่อคน/หน่วยงาน ชื่อขั้นตอนหรือเทมเพลตที่องค์กรตั้งเอง และข้อความอิสระอื่น ๆ ไม่ถูกแปลหรือเขียนทับ
- **อีเมลทุกชนิดและไฟล์ Export/รายงานที่ดาวน์โหลดได้** เช่น XLSX, CSV, PDF หรือไฟล์ Audit คงข้อความ โครงสร้างและรูปแบบเดิม รวมถึงข้อมูลที่โปรแกรมอื่นอ่านต่อ แปลเฉพาะหน้าจอก่อนกดส่งหรือดาวน์โหลด
- ข้อความแจ้งเตือนและบันทึก Audit เก่าที่เก็บเป็นประโยคสำเร็จรูปโดยไม่มีคีย์แปลให้แสดงตามเดิม ไม่เดาคำแปลจากประโยค ไม่เขียนทับประวัติ สำหรับแจ้งเตือนใหม่ให้ระบบบันทึกคีย์เพื่อแสดงได้สองภาษาในแอป
- ไม่ครอบคลุม API สำหรับระบบอื่น log สำหรับนักพัฒนา หน้าทดสอบ/preview ภายใน หรือข้อความที่เบราว์เซอร์และบริการภายนอกควบคุม ไม่เปลี่ยนปฏิทิน timezone หน่วยเงิน หรือรูปแบบข้อมูลที่ใช้ส่งและบันทึก

| Submit Request | ส่ง Request | ปุ่ม |

## แนวทางสำหรับการลงมือ

- เก็บค่าตามบัญชี เช่น `preferredLocale` รับเฉพาะ `th` หรือ `en` ให้ migration ตั้งค่าเริ่มต้นเป็น `en` การเขียนค่าบัญชีต้องใช้ session ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่รับ ID บัญชีจากตัวเลือกภาษา แยก cookie สำหรับหน้าที่ไม่ต้องล็อกอินโดยไม่เก็บข้อมูลบัญชีใน cookie นี้
- ให้เซิร์ฟเวอร์เลือกภาษาตั้งแต่แสดงผลครั้งแรก ส่งค่าเดียวกันให้เบราว์เซอร์และใช้กับ `lang` ของเอกสาร ไม่ใช้ cache ร่วมข้ามบัญชี ระบุภาษาของข้อความที่ตั้งใจคงไว้เมื่อจำเป็น ไม่เปลี่ยน URL หรือเส้นทางล็อกอินเดิม
- แยกชุดข้อความตามกลุ่มหน้า ใช้ key ตรงกันทั้ง `en` และ `th` พร้อมทดสอบความครบ ใช้ English เดิมเป็นฐาน ไม่ใช้คำที่แปลแล้วเป็น enum, filter value, route, key ของตาราง หรือเงื่อนไข workflow ตรวจรายการ production routes รวมหน้าต่างที่เปิดตามสิทธิ์และสถานะก่อนรับงาน
- ให้ UI แปลข้อผิดพลาดที่คาดไว้ผ่านคีย์คงที่ เพิ่มคีย์แบบไม่ทำให้จุดที่เรียกเดิมเปลี่ยนพฤติกรรม ไม่จับคู่จากประโยค English หรือส่งข้อความดิบจากฐานข้อมูลไปหาผู้ใช้
- เก็บคีย์และข้อมูลประกอบสำหรับแจ้งเตือนใหม่จากทุกจุดที่สร้างรายการ รวมที่สร้างใน transaction ให้แสดงตามภาษาของคนเปิดอ่าน ณ เวลานั้น คง `title`/`message` แบบเดิมไว้สำหรับข้อมูลเก่าและอีเมล ชื่อ Request และข้อความที่คนกรอกเป็นข้อมูลประกอบ ไม่ใช่ข้อความที่ต้องแปล
- สำหรับ Audit แปลตัวควบคุม หัวตาราง และชื่อเหตุการณ์ที่ระบุได้จากชนิดเหตุการณ์ แยกจากรายละเอียดดั้งเดิมที่ใช้ตรวจสอบย้อนหลัง ไม่แก้ payload, log หรือรูปแบบ Audit Export
- แบ่งงานเป็น: (1) ตัวสลับภาษา ชุดคำ และหน้าก่อนล็อกอิน (2) Request, Engineering และหน้าติดตามงาน (3) Admin, แจ้งเตือน และตรวจความครบทั้งแอป ทุกชุดอยู่ในขอบเขตส่งมอบเดียวกัน

## เกณฑ์รับงาน

1. บัญชีที่ยังไม่เลือกเห็น English; สลับบนหน้าเดิมได้ทั้งสองทิศทาง รีเฟรช เข้าระบบใหม่ หรือเข้าอีกเครื่องด้วยบัญชีเดียวกันแล้วยังได้ภาษาที่บันทึกไว้ ทดสอบว่าค่าหน้าก่อนล็อกอินและค่าจากบัญชีอื่นไม่เขียนทับบัญชี
2. มีรายการตรวจทุกหน้าที่เปิดใช้จริงในสองภาษา ครอบคลุมผู้ใช้ทั่วไป ผู้ทำ Solution ผู้อนุมัติ และ Admin รวมหน้าล็อกอิน โหลด ไม่มีข้อมูล ข้อผิดพลาด และ dialog ที่ไม่ได้เข้าจากเมนูโดยตรง ไม่มีข้อความตกหล่นนอกข้อยกเว้นที่ระบุ
3. ทดสอบ flow สร้าง Request → ส่ง Solution → Final ทั้งอนุมัติและส่งกลับให้แก้ ตรวจ URL ที่มี `requestId` สิทธิ์ ตัวกรองและค่า Status รวมถึงข้อมูลที่คนกรอก ทั้งหมดต้องทำงานเหมือนเดิม
4. แจ้งเตือนใหม่รายการเดียวกันแสดงได้สองภาษาเมื่อสลับบนหน้าจอ แจ้งเตือนเก่าอ่านได้ คลิกไป Request เดิม และการอ่าน/ยังไม่อ่านไม่เปลี่ยน ตรวจแยกว่าหัวข้อและเนื้อหาอีเมล รวมถึงคอลัมน์/เนื้อหาไฟล์ Export ไม่เปลี่ยนตามภาษาหน้าจอ
5. ทดสอบมือถือ เดสก์ท็อป คีย์บอร์ด และป้ายสำหรับโปรแกรมอ่านหน้าจอ ตัวเลือกและข้อความไทยไม่ถูกตัด ป้องกันค่าที่ไม่ใช่ `th`/`en` และการตั้งค่าข้ามบัญชี หากบันทึกไม่สำเร็จให้แสดงข้อผิดพลาดและอยู่ภาษาเดิม
6. รัน `npm run check` และทดสอบในเบราว์เซอร์บนสภาพแวดล้อมทดสอบ ไม่รัน production migration ในเครื่อง
