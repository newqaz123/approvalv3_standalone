# ImproveFlow: ตั้งค่าภาษาไทย / English

## เป้าหมาย

ให้ผู้ใช้เลือกภาษาที่อ่านง่ายเวลาสร้าง Request, ทำ Solution และอนุมัติงาน โดยคนที่ถนัด English ใช้งานต่อแบบเดิมได้ โหมดไทยใช้คำสั้น ๆ ที่คุ้นเคย และคงคำอย่าง Request, Solution และ Final ไว้เมื่ออ่านง่ายกว่าคำแปล

**ชื่อสถานะไม่แปลและไม่แก้** ทั้งชื่อที่เห็นบนหน้าจอและค่าที่ระบบใช้ กฎอนุมัติ สิทธิ์ และข้อมูลของ Request ไม่เปลี่ยนตามภาษา

## วิธีที่เลือก

- **จำตามบัญชี (เลือกวิธีนี้):** ค่าภาษาตามไปเมื่อใช้บัญชีเดียวกันบนคอมหรือมือถือ ต้องเพิ่มช่องเก็บค่าในฐานข้อมูล แต่ผู้ใช้ไม่ต้องเลือกใหม่ทุกเครื่อง
- **จำตามเบราว์เซอร์:** ไม่ต้องเปลี่ยนฐานข้อมูล แต่ไม่ตามผู้ใช้ข้ามเครื่อง และต้องแยกค่าให้ดีหากหลายบัญชีใช้เบราว์เซอร์เดียวกัน จึงไม่เลือก

## สิ่งที่ผู้ใช้เห็น

เมนูรูปโปรไฟล์เดิมใช้ทั้งมือถือและเดสก์ท็อป จึงเป็นจุดเดียวสำหรับเปลี่ยนภาษา:

```text
รูปโปรไฟล์ → ภาษา / Language → ไทย · English ✓
```

- ใช้ชื่อ `ไทย` และ `English` เหมือนกันทั้งสองโหมด ให้เห็นและอ่านได้ว่าภาษาไหนกำลังใช้อยู่ ใช้คีย์บอร์ดเลือกได้และแตะได้บนมือถือ
- บัญชีเดิมและบัญชีใหม่เริ่มที่ `English` จนกว่าจะเลือกเอง ไม่เดาภาษาจากเบราว์เซอร์
- เมื่อบันทึกสำเร็จ หน้าเดิมเปลี่ยนภาษาโดยไม่ต้องล็อกอินใหม่ ไม่เปลี่ยน path หรือ query string หากบันทึกไม่สำเร็จ ให้คงภาษาเดิมและบอกว่าลองใหม่ได้
- เข้าบัญชีเดิมบนอีกเครื่องหรือเข้าระบบใหม่แล้วใช้ภาษาที่บันทึกไว้ บัญชีอื่นไม่รับค่าภาษาของบัญชีก่อนหน้า

## ขอบเขตรอบแรก

| แปล | ไม่แปล / ไม่เปลี่ยน |
| --- | --- |
| เมนูนำทางร่วมและเมนูรูปโปรไฟล์ | ชื่อ Status ใน badge, รายการตัวกรอง, timeline และหน้ารายละเอียด รวมถึงสถานะการอนุมัติ เช่น `Pending`, `Approved`, `Rejected` |
| My Requests และ Pending Approvals: หัวข้อ ตาราง/การ์ด ข้อความตอนยังไม่มีรายการ และหัวข้อตัวกรอง เช่น `สถานะ` | ค่าที่เก็บในฐานข้อมูลและค่าที่ใช้กรอง เช่น `FinalApproval`; ชื่อที่แต่ละหน้ามีอยู่แล้วไม่ต้องปรับให้เหมือนกัน |
| รายการงานบนหน้า Engineering ที่ใช้เปิดงานส่ง Solution และหน้าต่างในขั้นตอน Request → Solution → Final: สร้าง เปิดดู ส่ง อนุมัติ ไม่อนุมัติ และส่งใหม่ตามที่ระบบรองรับ | เนื้อหาที่กรอกหรือตั้งค่าไว้ เช่น ชื่อเรื่อง รายละเอียด คอมเมนต์ เหตุผลที่ไม่อนุมัติ ชื่อคน/หน่วยงาน และชื่อขั้นตอนที่องค์กรตั้งเอง |
| ชื่อช่อง คำแนะนำ ปุ่ม ข้อความยืนยัน ข้อความแจ้งผล/ข้อผิดพลาดจากการทำรายการ และชื่อสำหรับโปรแกรมอ่านหน้าจอในส่วนข้างต้น | เนื้อหาหน้า Admin, Analytics, Budget, Sign In และหน้าอื่นนอกขั้นตอนหลัก; เนื้อหาในรายการแจ้งเตือน อีเมล ไฟล์ Export และรูปแบบวันที่/ตัวเลขยังเหมือนเดิม |

### ตัวอย่างคำ

| English | โหมดไทย | บริบท |
| --- | --- | --- |
| New Request | สร้าง Request | ปุ่ม |
| Submit Request | ส่ง Request | ปุ่ม |
| Pending Approvals | รอคุณอนุมัติ | เมนู ไม่ใช่ชื่อสถานะ |
| Submit Solution | ส่ง Solution | ปุ่ม |
| Submit for Final Approval | ส่งให้อนุมัติรอบ Final | ปุ่ม |
| Reject | ไม่อนุมัติ | ปุ่ม; badge `Rejected` คงเดิม |
| Final Approval / Completed / Cancelled | Final Approval / Completed / Cancelled | ชื่อสถานะ คงตรงกับหน้าปัจจุบัน |

ใช้คำไทยตรง ๆ เช่น “ยังส่ง Request ไม่ได้ ลองอีกครั้ง” แทนคำทางการหรือข้อความดิบจากระบบ และใช้คำเรียกเดียวกันในเมนู ฟอร์ม และข้อความแจ้งผล

## แนวทางสำหรับการลงมือ

- ใช้ค่าที่บัญชีผู้ใช้เป็นแหล่งข้อมูลหลัก เช่น `preferredLocale` ซึ่งเก็บ `th` หรือ `en` เท่านั้น ให้ migration ค่าเริ่มต้นเป็น `en` โดยไม่แก้ข้อมูลธุรกิจ การบันทึกต้องอ้างบัญชีจาก session ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่รับ ID บัญชีจากตัวเลือกภาษา
- ให้ฝั่งเซิร์ฟเวอร์เลือกภาษาตอนแรกที่เรนเดอร์ และส่งภาษาเดียวกันให้ส่วนที่รันในเบราว์เซอร์ ใช้ค่าเดียวกันสำหรับ `lang` ของเอกสาร และระบุภาษาของส่วนที่คงเป็น English เมื่อจำเป็น หลีกเลี่ยงการแสดง English แวบแรกก่อนเปลี่ยนเป็นไทยในหน้าที่แปลแล้ว
- รวมข้อความเป็นชุด `en`/`th` แบบมี key ร่วมและมีวิธีตรวจความครบ ใช้ข้อความ English เดิมเป็นฐานและเป็น fallback หากภาษาไม่รองรับ ไม่ใช้ข้อความแปลเป็นค่า filter, enum, route, key ของตาราง หรือเงื่อนไข workflow
- สำหรับข้อผิดพลาดที่คาดไว้ ใช้รหัสหรือคีย์ที่คงที่ให้ UI เลือกข้อความตามภาษา ไม่จับคู่จากประโยค English และไม่แสดงข้อความดิบจากฐานข้อมูลหรือ stack trace หากต้องเพิ่มคีย์ ให้เพิ่มแบบไม่ทำให้จุดที่เรียกเดิมเสีย
- ใช้ URL และระบบล็อกอินเดิม ไม่ทำ `/th` หรือ `/en` และไม่เปลี่ยนวิธีส่ง อนุมัติ หรือส่งกลับงานเพื่อรองรับการแปล การเลือกวิธีส่งชุดคำและรายละเอียดของการรีเฟรชหน้าให้ตัดสินในแผนลงมือ

## เกณฑ์รับงาน

1. บัญชีที่ยังไม่เลือกเห็น English; เมื่อเลือกไทย เมนูและข้อความในขอบเขตเปลี่ยนบนหน้าเดิม สลับกลับได้ และเปิดหน้าใหม่ รีเฟรช หรือเข้าเครื่องอื่นด้วยบัญชีเดียวกันแล้วยังได้ภาษาที่บันทึกไว้
2. ทดสอบด้วยบัญชีที่มีสิทธิ์ตามงานจริง: ผู้ส่งสร้าง Request, ผู้ทำ Solution ส่ง Solution, ผู้อนุมัติเปิดและตัดสินใจจากรายการรออนุมัติ จนถึง Final ใช้กรณีส่งกลับและส่งใหม่ประกอบด้วย ตรวจว่า URL ที่มี `requestId` และสิทธิ์เดิมยังใช้ได้
3. เทียบข้อความสถานะในตาราง การ์ด ตัวกรอง และ timeline ระหว่างสองภาษา ต้องเหมือนเดิม รวมถึงตัวเลือกที่เลือกอยู่และผลกรอง ข้อความที่ผู้ใช้กรอกต้องไม่ถูกแก้หรือแปล
4. ลองด้วยเมาส์ คีย์บอร์ด และมือถือ: เลือกภาษาได้ เห็นค่าเลือกปัจจุบัน อ่านตัวเลือกและปุ่มไทยได้ไม่โดนตัด และเมื่อบันทึกไม่สำเร็จยังอยู่ในภาษาเดิม
5. ตรวจทั้งข้อความฝั่งเซิร์ฟเวอร์และฝั่งเบราว์เซอร์ รวมกรณีป้อนภาษานอกเหนือจาก `th`/`en` และการทดสอบป้องกันการตั้งค่าข้ามบัญชี รัน `npm run check` และทดสอบ flow ในเบราว์เซอร์บนสภาพแวดล้อมทดสอบ ไม่รัน production migration ในเครื่อง
