Exactly the existing 44 supported primary IDs (rank 28/custom 16) in **each** fresh pass: `all-defaults` 12, `solution-exception` 11, `final-exception` 11, `solution-and-final-exceptions` 10. Two passes mean 88 new executions, **eight serial invocations**, one newly allocated empty owned runtime **per profile-pass**, and a new request **per case**. Historical 29 distinct passing-evidence IDs substitute for neither pass. “100%” can mean only this defined supported inventory, never bug-free or release acceptance. Owner-approved, hash-pinned invocation manifests supply pass/invocation/profile/expected IDs, strict-assurance source identity and evidence root **before** launch. The actual owned runtime binds that immutable authority to its new run ID; the binding propagates through session/action/proof/case artifacts. Completion entries are produced only from qualified persisted case and invocation artifacts after all case/stop/review/parent gates, never by stamping a pass label at inventory time. Acceptance dereferences and verifies those digests, identities and qualification against canonical authority and prior accepted-pass artifacts: exactly eight invocation/runtime groups and 88 unique newly created request IDs. Cases in one profile-pass intentionally share its runtime; the same 44 case IDs and fixture actor UUIDs legitimately recur across passes. Expected rejection is a **positive business mutation**, not an unchanged denial. Allowed denials and UI-only negative checks have their own satisfiable gates, not an all-COMMITTED rule. REQUEST custom creation, REQUEST/SOLUTION stale POST, direct-link authorization, download/export/sharing and product release remain explicit gaps. Loaded-list absence proves none of those. ## 2. Required per-action proof

Durably record a discriminated `ActionRecord` before the one business click. Rowless create/submit/initiate/resubmit attempts remain explicit even when the snapshot or row target is null; never clear the journal to hide ambiguity. The plan's eleven-export registry covers every phase caller. For each action correlate: run/pass/profile/case/context/action sequence; intended actor versus **original server authentication result**; module/export and fresh public action ID; privacy-safe actual argument projection; exact request/solution/instance/row, phase-local attempt, order/current turn, group ID and complete membership; browser dispatch/result/error; generated source/served build; and action-specific persisted before/after proof, audit, notifications and isolated mail semantics.

All these proof classes are mandatory for dispatched actions. Missing/wrong handler, actor, target, current turn, response, source/build, snapshot or required artifact fails evidence; public bindings, HTTP 200, toast and optimistic labels prove no handler entry or commit. There must be exactly one matching dispatch/invocation; ambiguity fails. REQUEST/SOLUTION commits use their own state/row/attempt proofs, never new FINAL counts.

Lifecycle findings distinguish pre-invocation observer failure, unobserved dispatch (not proof of a client queue), absent/incomplete response, expected unchanged denial, thrown noncommit, returned noncommit, committed/UI-confirmed, committed/UI-failed and evidence failure. Transaction resolution plus action-specific persisted transition proves commit; a throw alone or no new FINAL rows proves neither rollback nor noncommit. Missing required proof overrides acceptance while retaining any independently proven commit as a fact. No retry, replay, second business invocation or API injection follows any failure.

## 3. Small source-bound observer

Future checked-in edits stay in the existing four matrix files only; generated diagnostics exist **only in a disposable owned app copy**. No permanent product logging, dependency, shared fixture/schema/config change, global monkeypatch or extra authentication/business probe. Runtime uses TypeScript AST source-match transforms, reviewed source SHA256, exact eleven-export registration and ownership/realpath guards. Generate one private non-`use server` observer module plus transforms in copied `requests.ts`, `approvals.ts`, `solutions.ts`; no new public action export. Compile the copy explicitly before app/browser/business work. Source/AST mismatch, incomplete registration or failed compilation blocks startup.

At handler entry, durable observer BEGIN admission can fail **before invoking original logic** (`OBSERVER_FAILED_BEFORE_INVOCATION`, zero business calls). Once original logic starts, telemetry must never replace its result or exception. Capture the existing `getCurrentUser()` result for createRequest (user-cache authenticates by session), and existing `_authUser`/`userId` for the other ten exports. Tap, without replay, original transaction resolution/rejection; the private solution transaction helper receives an explicit invocation token in the generated copy so transaction resolution is observed before post-commit notifications. No duplicate auth, transaction or query. Preserve original guard order, original callback/options, return object and thrown object. Actor, transaction and exit observations are nonthrowing after invocation; failures remain mandatory evidence gaps/sticky observer faults. A post-commit logging fault fails the host evidence gate and stops the next action **without inventing a business failure or replaying the committed action**. If these source-matched transformations cannot preserve semantics or fit the boundary, STOP as `BLOCKED_OWNER_DECISION` with the exact unmet proof and proposed scope; do not silently substitute client/audit proxies.

## 5. Capture, clocks and privacy

At the real `playwrightMatrixUi` nested `newContext` factory, register **context** capture immediately after `browser.newContext`, before tracing/newPage/sign-in/navigation. Any later manual session factory must use the same hook before page work; an unregistered context is inadmissible. Archive exact served public JS bytes under each context, SHA256 and fresh `createServerReference` export/action-ID bindings with source offsets; verify actual used bindings against the source registration. Do not read/export private build-manifest encryptionKey or treat historical fingerprints as fresh authority. Record every relevant response/error and bounded missing-body disposition. Decode Next **15.5.23** Flight action result (`response.a`, including promise/model references and error chunks), not generic JSON/200. Full transport completion, resolvable result graph and allowlisted result/error projection are required; unresolved/unsupported references, truncation, redirect/no result, missing body or unfinished stream fail closed.

Keep original raw wall/monotonic domains and start/end fields, with per-context clock anchors and measured uncertainty; no cross-domain subtraction without a mapping, no HAR-duration cause inference. Track every capture/artifact write and drain before action confirmation, PASSED, progress/case/aggregate finalization. Capture shares the **operation's existing result-wait deadline**: held stale confirm 15,000 ms (M:767–775), applicable positive-result waits 30,000 ms (M:583,619,661,701,816,835,871), without resetting/extending either. Separate evidence-only close/stop drains are 5,000 ms, not extra business-result time; opener/prerequisite/navigation/screenshot budgets are unchanged and not result deadlines. Unfinished bodies become explicit incomplete evidence before owned shutdown, not an indefinite wait for a body needing that shutdown. Late callbacks cannot change finalized artifacts. Retain primary + capture + artifact + progress + stop + close errors. No new sleeps, business retries or timeout increases as an RRM-030 fix.

Review packets allow only isolated IDs, flags, ordered fixture actors, content hashes, safe result/error codes and clock/build metadata; exclude cookies/passwords/credentials/tokens, real SMTP and opaque encrypted closure payloads. Raw allowlisted action Flight/JS material stays in restricted owned evidence; no arbitrary headers/request payload export. Original fixture traces retain their existing private boundary and may contain the sign-in password; do not claim otherwise.

## 6. Operational barriers and unknowns

Before implementation: fresh independent design/plan review and parent/owner approval. After separately authorized code changes: focused regressions (preserve original 86), full `npm run check`, graph update, generated-copy compilation/observer verification and independent native readiness review; parent launch clearance is separate. Before each next profile: visual review, native checked evidence, verified owned stop, independent review, parent clearance. Each pass must independently contain all 44 distinct IDs and required negatives. Any case/evidence/runtime failure stops **all** subsequent cases/profiles pending owner disposition; no automatic fix/retest/relaunch loops.

Operator pause disables new action admission, finishes the already admitted action within its existing bounded deadline, drains evidence, closes contexts and stops only verified owned resources. Unknown in-flight fate retains an attempting action and blocks continuation; no SIGSTOP mid-business-action, no assumed uninterrupted qualification after resume. A paused/truncated invocation is not a qualifying uninterrupted profile-pass; retained IDs do not fill a new pass. Model quota 429 does not freeze/cancel a healthy autonomous driver or authorize provider switching. Future warnings/control use the current owned run manifest and monitor/control records (run ID, PID/start identity, ports, resource ownership), not old ports or stale monitors.
